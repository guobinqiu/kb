# KB API V1 Implementation Plan

**Goal:** Implement the first runnable KB API for authentication, scoped management, MinIO file storage, and RabbitMQ indexing workflows.

**Architecture:** FastAPI delegates persistence to an injectable repository and external I/O to injectable storage and queue clients. Tests use a dedicated PostgreSQL test database with in-memory storage and queue collaborators.

**Tech Stack:** Python 3.11+, FastAPI, psycopg 3, MinIO, RabbitMQ/pika, pytest

## Global Constraints

- Only change files under `kb_api`; do not modify `webui`, `deploy`, or `rag_indexer`.
- PostgreSQL schema is `kb`; tables are `apps`, `orgs`, `users`, `workspaces`, `workspace_user`, `workspace_org`, and `files`.
- Each App has one org tree with a root whose `parent_id` is null. The platform owner has no org.
- A user's login name is stored as `name` and org identity as `org_id`; workspace membership owns file access scope.
- Queue name is exactly `kb.index.tasks`; index results are written back through `POST /api/v1/index-results`.
- Write and run failing tests before production implementation.
