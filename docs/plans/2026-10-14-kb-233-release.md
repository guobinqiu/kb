# KB 233 Release Implementation Plan

**Goal:** Commit the current KB changes and deploy that commit to `imsdom@19.16.1.233` without overwriting unrelated remote state or silently discarding production data.

**Architecture:** Verify the local worktree and tests, commit and push a single reviewed KB revision, then fast-forward the 233 checkout. Reconcile the existing remote Qdrant override and PG16 data with the requested PostgreSQL/ParadeDB PG17 deployment before recreating containers. Validate service health, queue consumption, and host-based routes after rollout.

**Tech Stack:** Git, Docker Compose, ParadeDB/PostgreSQL, RabbitMQ, Nginx, pytest, Node.

## Global Constraints

- Local repository: `/Users/guobin/workspace/kb`; remote repository: `/home/imsdom/workspace/kb`.
- Target only the KB Compose projects; leave unrelated 233 services, MinerU, TEI, and KB3 untouched.
- Current remote `kb_api/config/rag.yaml` has an uncommitted Qdrant override; preserve it until the requested PostgreSQL switch is reconciled.
- Current remote `pg_data` is PostgreSQL 16 with existing business data; `paradedb/paradedb:v0.22.6-pg17` cannot use that directory directly.
- Do not choose between migrating existing 233 data and initializing an empty database without the user's answer.
- Do not print `.env` secrets or delete Docker volumes.

### Task 1: Local release gate

**Files:** Current tracked and untracked KB changes, including `deploy/`, `kb_api/`, `webui/`, `scripts/`, and `docs/`.

**Interfaces:** The commit is the sole input to the 233 fast-forward update.

- [ ] Review `git status --short`, `git diff --check`, and the complete staged diff before committing.
- [ ] Validate each Compose file with `docker compose --env-file deploy/env.example -p kb-check -f deploy/<file>.yaml config -q`.
- [ ] Initialize only the local `rag_test` test schema with `docker exec -i kb_postgres psql -v ON_ERROR_STOP=1 -U rag -d rag_test < scripts/test_db.sql` if required by the current schema.
- [ ] Run the existing API, Indexer, and WebUI checks listed in `README.md`; do not add new tests for this release operation.
- [ ] Stage reviewed KB files, inspect `git diff --cached --check` and `git diff --cached --stat`, then commit with a message describing deletion, indexing fallback, and deployment changes.
- [ ] Push `main` to `origin/main`; verify the pushed revision matches local `HEAD`.

### Task 2: Remote preflight and data decision

**Files:** Remote `/home/imsdom/workspace/kb/kb_api/config/rag.yaml`, `/home/imsdom/workspace/kb/pg_data`, and `deploy/.env`.

**Interfaces:** The selected data path determines how PG17 is started; the existing `.env` and external model services remain in place.

- [ ] Record remote `git status --short --branch`, `git rev-parse HEAD`, Compose labels, image tags, mounts, available disk, and listening ports.
- [ ] Record aggregate counts in the existing PG16 database and verify the old Qdrant override is the only remote worktree change.
- [ ] Wait for the user's explicit choice: migrate remote business data to PG17 or start with an empty database. Do not re-create `postgres` before this decision.
- [ ] Check `/etc/hosts` and `sudo -n true`; add only the requested KB domain entries when the deployment is ready.

### Task 3: 233 rollout

**Files:** Remote KB checkout, Compose services, and the data location selected in Task 2.

**Interfaces:** `web.kb.test`, `api.kb.test`, and `chat.kb.test` route through `kb_nginx` on port 80; vector storage is PostgreSQL, not Qdrant.

- [ ] Preserve the remote Qdrant config override in a recoverable Git stash, then fast-forward the checkout to the pushed commit.
- [ ] Perform only the user-selected PG16-to-PG17 data operation; confirm PG17 can start with the resulting `pg_data` before rebuilding application containers.
- [ ] Apply `scripts/db.sql` with `ON_ERROR_STOP=1` and verify `vector` and `pg_search` extensions.
- [ ] Recreate the KB infra, API, Indexer, Chat, WebUI, and Nginx Compose projects using their repository commands; keep MinerU and TEI running.
- [ ] Verify the running `kb_` container names, PG17 image, API/Indexer/RabbitMQ health, one `kb.index.tasks` consumer, and all three domain routes.
- [ ] Report the commit SHA, remote revision, data choice, validation evidence, and any remaining operational limitations.
